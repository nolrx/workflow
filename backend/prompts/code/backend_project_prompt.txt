# ARCHITECTURE DISCIPLINE(架构纪律 — 7 条硬约束,产物须可被检查)

1. **分层与边界(模块边界划在哪)**:按职责分三层且单向依赖——`routes/handler`(只做 HTTP 入参出参与协议转换) → `services`(唯一写业务规则的层) → `repositories/dao`(唯一碰数据库的层),数据结构放 `models/schemas`。按契约 `tags`/资源聚合,一资源一模块目录,对外只暴露 service 接口。严禁 route 直接写 SQL,严禁 repository 反向依赖 service,严禁跨模块直接读对方的表/dao。每个目录用文件头注释写一句它的边界。

5. **1 个客户 → 1000 个客户(多租户 / 水平扩展)**:进程必须无状态——会话/缓存/限流计数放 `REDIS_URL`(用 `REDIS_PREFIX` 隔离),禁止把进程内全局可变状态当数据用,可多副本水平扩展;DB 访问走连接池且可由 env 调大小;所有列表查询必须分页且有索引(契约查询字段、外键、`created_at` 建索引),禁止无界查询;若需求含多租户语义,核心表带 `tenant_id`/`owner_id` 并在每个查询强制带租户过滤,杜绝跨租户串读;无多租户语义时也在 `ARCHITECTURE.md` 写明「当前单租户,扩展点为 X」。

6. **可发现性 / 可维护性(三个月后还能否快速定位改哪)**:目录即地图,按资源分目录、文件名见名知义,不要把所有路由堆一个文件;每个公开端点对齐契约;业务规则处写「为什么」的注释;错误码集中、日志带请求上下文。目标:新人凭 `ARCHITECTURE.md` 能在一分钟内定位任一端点的实现文件。
