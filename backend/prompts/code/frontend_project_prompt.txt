# OUTPUT CONTRACT (authoritative)(产出契约 — 唯一权威输出结构)
**本契约优先于上方任何通用结构化建议,冲突以此为准。** 本阶段产出形态是 **agent-files**:你要在容器内**真实创建文件、运行命令、并自检构建**,而不是输出 JSON 或描述。最终只回一句话总结(见末尾)。必须满足以下全部硬性技术契约(产物会被自动构建校验,违反将被判失败):

1. **技术栈**:React 19 + TypeScript + Vite + 纯 CSS(每个组件配套同名 .css)。**禁止 Tailwind、禁止任何 UI 组件库、禁止任何 CDN / 远程资源 / 远程字体 / 运行时网络请求。** 注意:由 image-assets 技能在构建期生成、保存在 `src/assets/` 下的本地图片**不算**远程资源(它们会被 Vite 打包成本地文件,运行时不发任何网络请求),可放心使用。

2. **工程结构**:组件拆到 `src/components/`;状态用 React hooks;类型集中在 `src/types.ts`;图片资源统一放 `src/assets/`。组织上对齐开发流程的模块(M)划分。**数据持久化分两种模式**:
   - **全栈模式(上方「共享 API 契约」非空)**:前端所有数据读写都**调用真实后端**,不要用 localStorage 充当数据源。封装一个 API 客户端,基址按如下顺序解析:`window.__API_BASE__`(部署时由平台注入)→ `import.meta.env.VITE_API_BASE_URL` → 默认 `'/api'`;然后**严格按共享 API 契约**逐端点调用(method/path/字段与契约一致,路径相对基址,如 `${base}/orders`)。要处理 loading / error / 空态。仅 UI 偏好等非业务数据可用 localStorage。
   - **独立模式(契约为空)**:沿用 localStorage 持久化,并在首次加载时播种合理的示例数据。

3. **vite.config.ts 必须设置 `base: './'`(相对路径)**,以便构建产物能在子路径下的 iframe 内预览。

4. **所有交互必须真实可用**:每个按钮/链接/菜单都有真实事件;每个输入/选择/表单都改变有意义的状态且有提交行为。**禁止死控件、禁止 `href="#"` 空链接、禁止空事件处理器。** 禁止 TODO / FIXME、占位、"未实现"、"coming soon"、仅 mock 的界面——一律用内存/localStorage 状态实现真实功能。

5. **逐 FR 落地**:需求文档中的每条功能需求(FR)都要有对应的可操作 UI 入口与真实行为,能在界面中演示;优先完整流程而非装饰性填充,合理覆盖核心功能。

6. **构建自检(必做)**:你必须亲自依次运行 `npm install` 和 `npm run build`,若有报错就修到**两条命令都成功**为止。**不要运行 `npm run dev`、`vite preview` 或任何长驻/不退出的进程。**

7. **真实图片资源(硬性验收项)**:必须用 `gen-assets` 命令(image-assets 技能的执行器,触发 Codex 子 Agent 调用图像模型)生成 **3~6 张真实位图**到 `src/assets/`,并在界面中 import 引用。流程:
   - 规划阶段先确定本产品需要哪些关键图片(用途/主题/风格/建议尺寸:主视觉/插画/照片/头像/产品图/背景等)。
   - 用 Bash 直接运行 `gen-assets`(一次可描述多张,每张写明 `src/assets/` 下的目标路径),例如:
         gen-assets "1) src/assets/hero.png — 现代简约 SaaS 仪表盘工作场景照,冷色调,1536x1024; 2) src/assets/avatar-1.png — 职业人物头像,中性背景,1024x1024; 3) src/assets/feature-1.png — 产品功能示意插画,扁平风,1024x1024"
     若提示 `gen-assets: command not found`,改用绝对路径 `/home/node/bin/gen-assets "..."`。
   - 命令返回后,用 `ls src/assets` 确认对应 PNG 文件确实已生成。
   - 在组件中通过 import 引用(Vite 会打包并按 `base './'` 重写路径,保证子路径 iframe 预览也能加载):
         import heroUrl from './assets/hero.png'
         // <img src={heroUrl} alt="产品概览" />
   - **必须真的执行 `gen-assets` 命令**(不要只在脑海里假设有图,也不要写不存在的 import 路径)。除非产品本质上完全不需要任何图片(如纯计算器),否则未生成任何图片资源将判为不合格。

8. **视觉保真(高度仿真)**:目标是"看起来像真实上线的产品",而非线框/Demo——层级、留白、阴影、圆角、状态(hover/active/focus/disabled)、空态/加载态都要打磨到位。内容真实可信:用贴合产品语境的真实文案、人名、数据与列表,**不要 "Lorem ipsum"、"示例1/示例2" 这类占位内容**。

9. **严格控制 emoji**:**不要把 emoji 当作图标、插画、Logo、头像或界面装饰。** 功能性图标用内联 SVG;图片/插画/照片一律用 `gen-assets` 生成真实位图。仅当 `gen-assets` 明确报错(command not found / 未配置 key / 生成失败)时,才退而用克制的 CSS 渐变、纯色块或内联 SVG 兜底,并在最终总结里**写明 gen-assets 失败的原因**;即便如此也**绝不**用 emoji 充当图片。仅在确实表达情绪的正文文本里可偶尔出现 emoji,且整体克制。

10. **完成后总结**:用一句话总结——生成了哪些主要文件、**实际执行 gen-assets 生成了哪些图片资源(若失败请写明原因)**、应用有哪些可交互功能、`npm run build` 是否通过。
