# OUTPUT CONTRACT (authoritative)(产出契约 — 唯一权威输出结构)
**本契约优先于上方任何通用结构化建议,冲突以此为准。** 本阶段产出形态是 **agent-files**:你要在容器内**真实创建文件、运行命令、并自检构建**,而不是输出 JSON 或描述。最终只回一句话总结(见末尾)。必须满足以下全部硬性技术契约(产物会被自动构建校验,违反将被判失败):

1. **技术栈**:React 19 + TypeScript + Vite + 纯 CSS(每个组件配套同名 .css)。**禁止 Tailwind、禁止任何 UI 组件库、禁止任何 CDN / 远程字体 / 第三方外部资源请求(外部 JS/CSS、图床、外部 API、远程字体等)。** ⚠ 这里禁止的是"**第三方外部**"网络请求;**全栈模式下对自己的同源后端 API(经平台反代的 `/api/...`)的请求是必须的、不在禁止之列**——禁令的目的是杜绝外部依赖,不是阻断你调用自己的后端。注意:由 image-assets 技能在构建期生成、保存在 `src/assets/` 下的本地图片**不算**远程资源(它们会被 Vite 打包成本地文件,运行时不发任何外部网络请求),可放心使用。

2. **工程结构**:组件拆到 `src/components/`;状态用 React hooks;类型集中在 `src/types.ts`;图片资源统一放 `src/assets/`。组织上对齐开发流程的模块(M)划分。**数据持久化分两种模式**:
   - **全栈模式(上方「共享 API 契约」非空)**:前端所有数据读写都**调用真实后端**,不要用 localStorage 充当数据源。封装一个 API 客户端,基址按如下顺序解析:`window.__API_BASE__`(部署时由平台注入)→ `import.meta.env.VITE_API_BASE_URL` → 默认 `'/api'`;然后**严格按共享 API 契约**逐端点调用(method/path/字段与契约一致,路径相对基址,如 `${base}/orders`)。要处理 loading / error / 空态。仅 UI 偏好等非业务数据可用 localStorage。
   - **接口规范:统一拆信封(全栈模式必做 — 与后端出参逐字一致)**:后端所有响应都是统一信封——成功 `{ success:true, data, message }`,失败 `{ success:false, error, message }`。**API 客户端在一处统一处理**:HTTP 非 2xx **或** `success===false` 一律当失败抛出(带上 `error` 码与 `message` 给 UI 展示),成功则**只取 `resp.data` 作为业务数据**交给上层(组件不要各自去摸 `success`/外壳)。列表分页固定从 `data.items` / `data.total` / `data.page` / `data.page_size` 读取;**不要假设后端返回裸数组**。字段名严格按契约 schema(snake_case、id 为字符串、时间 ISO-8601),不要在前端臆改字段名。
   - **独立模式(契约为空)**:沿用 localStorage 持久化,并在首次加载时播种合理的示例数据。
   - **登录鉴权(全栈模式且契约含 `/auth/login` 时必做 — 与后端登录口径逐字一致,固定不可发挥)**:实现真实登录页与登录态,**token 字段名 / 请求头 / `/auth/*` 路径必须与契约逐字一致**,任何不一致都会导致登录失败或 `401` 风暴。
     1. **登录**:向 `${base}/auth/login` POST `{ email, password }`(passwordless 则按契约先 `${base}/auth/request-code` 取码,再 `${base}/auth/login` 提交 `{ phone/email, code }`);**成功后从 `resp.data.token` 读取 token(随统一信封落在 `data.token`,固定就叫 `token`,是 JWT 字符串)**,连同 `resp.data.user` 存入 localStorage——**token 固定存到键 `auth_token`**。
     2. **带 token**:API 客户端在**每个请求**上,当本地存在 token 时附加请求头 `Authorization: Bearer <token>`(**固定用此头,不要用 cookie / query / 自定义头**)。
     3. **前端如何验证通过(登录态判据)**:以「本地是否存在有效 token」为登录态——未登录时用路由守卫把受保护页面挡在登录页之外;应用启动时可调 `GET ${base}/auth/me` 校验本地 token 是否仍有效,无效则清除并回登录页。
     4. **401 兜底**:任意请求返回 `401` 时,统一清除本地 `auth_token` 并跳转登录页(token 过期/失效的兜底);并提供登出(清 token 回登录页)。
     5. 登录页可预填 demo 凭据(`demo@example.com` / `Demo1234!`,passwordless 则提示固定开发验证码 `000000`)方便体验。
   - **实时通道(全栈模式且契约 `realtime.enabled=true` 时必做 — 与契约 `realtime` 逐字一致)**:实现真实的 **WebSocket** 连接,**通道路径 / 鉴权方式必须与契约 `realtime` 逐字一致**;契约 `enabled=false`(或无 `realtime` 段)时**不要引入任何 WS**。
     1. **ws 基址解析**:按 `window.__WS_BASE__`(部署时由平台注入,**与 HTTP 同一个 api 基址**,如 `/app/<项目>/api`)→ 回退 `window.__API_BASE__` → 默认 `'/api'`。再解析成绝对 ws URL:相对路径用 `window.location` 补全 host,并按页面协议把 `https→wss`、`http→ws`(如 `${location.protocol==='https:'?'wss':'ws'}://${location.host}${wsBase}`)。
     2. **连接 + 鉴权**:连 `${wsUrl}${契约通道 path,如 /signal}?token=${auth_token}`——浏览器 WebSocket 不能设 `Authorization` 头,故把登录存下的 `auth_token`(即 `data.token`)**作为 `?token=` 查询参数**携带(与契约 `auth: "query_token"` 一致),**不要用 header / cookie 鉴权**。ws 与 HTTP 走同一个 `/api` 基址,平台靠 `Upgrade` 头把它直连到后端,**无需也不要拼 `/ws` 之类的额外前缀**。
     3. **统一帧**:收发都按统一帧 `{ type, data, ts }`(JSON 文本)解析与构造;按 `type` 分发更新对应 UI 状态。
     4. **健壮性**:断线指数退避重连(带次数/间隔上限);组件卸载 / 登出 / 收到 `401` 时关闭连接并停止重连;未登录 / 无网络时优雅降级,不要崩。

3. **构建产物必须能在「未知子路径」下独立运行**(平台会把它挂在 `/preview/<项目id>/` 这类带前缀的路径上服务,构建期并不知道该前缀)。为此有两条不可违反的约定:
   - **静态资源相对化**:`vite.config.ts` 必须设置 `base: './'`(相对路径),让 JS/CSS/图片按相对路径加载,不要写死 `/assets/...` 这种根绝对路径。
   - **路由必须用 hash 路由,严禁 history 路由(关键)**:若工程使用 react-router,**必须用 `HashRouter`**(`import { HashRouter } from 'react-router-dom'`,把它包在最外层),**禁止 `BrowserRouter` / `createBrowserRouter` / 任何 history 模式**。原因:产物挂在 `/preview/<项目id>/` 前缀下、构建期拿不到该前缀,history 路由会把 `/login`、`/dashboard` 之类**当作根绝对路径**推到主域名(`https://<主站>/login`),导致点击后**跳出预览、落回平台主站**,深链刷新也会 404;而 hash 路由把全部路由放进 URL 的 `#` 片段,既不会离开 `/preview/<项目id>/`、刷新也始终命中 `index.html`,与 `base: './'` 同样是"对挂载路径无感知"。`<Link to="/x">` 在 `HashRouter` 下会自动渲染成 `#/x`,正常写即可。
   - **禁止任何逃出当前子路径的硬跳转**:不要用 `<a href="/...">`、`window.location.href = '/...'`、`location.assign('/...')`、`history.pushState(_, _, '/...')` 等**根绝对路径**导航(它们同样会跳到主域名);页面内导航一律走 hash 路由或相对路径。若不用路由库(纯 state 切换视图)则天然无此问题。

4. **所有交互必须真实可用**:每个按钮/链接/菜单都有真实事件;每个输入/选择/表单都改变有意义的状态且有提交行为。**禁止死控件、禁止 `href="#"` 空链接、禁止空事件处理器。** 禁止 TODO / FIXME、占位、"未实现"、"coming soon"、仅 mock 的界面——一律用内存/localStorage 状态实现真实功能。
